Every action an AI agent takes, gated by deterministic rules and recorded as evidence an auditor can verify without trusting us.

QED is one self-hosted process between an agent and whatever it is about to touch — an MCP server, an HTTP API, a database, a coding agent's tool call. For each action it produces a verdict from a signed policy bundle, and appends the proposal and the verdict to an Ed25519 hash-chained ledger.

There is no model in the decision path. Identical inputs produce byte-identical output, and a test fails the build if an LLM SDK is ever imported into the kernel.

Apache-2.0 self-hosted offline by default Python 3.12+ evidence format 1.0, frozen

Two commands

Three parts

Decide

A verdict is a pure function of the proposal, the policy bundle, the budget and a derived context. 46 baseline rules ship, covering identity, blast radius, data, skills and budget; you write your own in YAML and test them with qed policy test.

Record

Every proposal, verdict, approval and key rotation is appended to a hash-chained ledger, signed with Ed25519 and checkpointed into a Merkle root. Payloads can be purged for GDPR and the chain still verifies, because the hash covers the payload's digest and not the payload.

Verify

qed-verify is a separate package whose only dependency is cryptography, written as an independent reimplementation of the format from its specification. It never contacts the instance that produced the records. Agreement between two implementations is the claim.

What it will not do

  • Print a compliance percentage it cannot stand behind. Where a control catalogue is partial, qed packs list says partial and names what is missing. ISO 42001's Annex A is not mapped at all, because the standard is not freely published and inventing control titles would be worse than a gap.
  • Claim it stopped something when it only said no. An adapter that does not hold the credential can tell an agent no; it cannot stop an agent that ignores it. Every record carries which of the two it was, and qed doctor says it in plain words: none configured, so every adapter is ADVISORY.
  • Pretend a Merkle root you computed yourself proves anything. Until you configure an external anchor, qed doctor reports that the root attests to nothing an operator who could rewrite the chain could not recompute.
  • Put a model in the decision path. Not as a fallback, not for "ambiguous" cases. A probabilistic component in a control an auditor signs off on is not a control.
  • Hide what a green test suite missed. docs/validation.md lists every bug that shipped past a passing suite, with the reason each one was invisible — including a mandate signature nothing verified for eight weeks while its unit tests passed.

Install

# from the repository, which works today
$ git clone https://github.com/valqore/qed && cd qed
$ pip install -e .
$ qed keys init && qed doctor

# once the names are reserved -- see the notice at the top of this page
$ pip install valqore-qed
$ brew install valqore/tap/qed
$ docker run ghcr.io/valqore/qed:1.0.0 serve

Start in shadow mode, where QED decides and records and tells the agent to proceed regardless. The shadow-to-enforce guide is six stages long and the only one that matters is stage 3: read the gap between decision and would_decision before you turn anything on.
